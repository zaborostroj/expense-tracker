# Инициализация и запуск базы данных PostgreSQL

Данная конфигурация предназначена для развертывания и первичной инициализации СУБД PostgreSQL в Docker для сервиса аутентификации (`auth-service`).
Скрипты создают только роли, базы и схемы. Наполнение таблицами и данными - ответственность liquibase.

---

## Структура компонентов

- **`docker-compose.yml`** — манифест сервиса `postgres` (версия `postgres:16`). Настраивает проброс портов (`55432:5432`), персистентное хранилище `./db-data/`, переменные окружения и монтирование скриптов инициализации.
- **`db_init.sh`** — bash-скрипт инициализации, монтируемый в `/docker-entrypoint-initdb.d/`. Автоматически запускается официальным entrypoint-скриптом PostgreSQL при первом старте контейнера (когда каталог данных пуст).
- **`db_init.sql`** — SQL-скрипт, содержащий DDL-команды создания ролей, БД, схем и прав доступа.

---

## Порядок инициализации

1. **Запуск контейнера и проверка тома данных:**
   - При старте контейнера PostgreSQL проверяет наличие существующего кластера в `/var/lib/postgresql/data`.
   - Если кластер инициализируется впервые, запускаются исполняемые скрипты из `/docker-entrypoint-initdb.d/`.

2. **Выполнение `db_init.sh`:**
   - Скрипт подключается через утилиту `psql` от имени суперпользователя (`POSTGRES_USER` / `postgres`) к базе `POSTGRES_DB`.
   - Передает пароль приложения (`AUTH_APP_PASSWORD`) в SQL-скрипт через переменную `auth_app_password`.
   - Исполняет файл `/scripts/db_init.sql` с флагом `ON_ERROR_STOP=1` (аварийная остановка при любой ошибке).
   - Обязательно должен быть исполняемым (`chmod +X db_init.sh`)

3. **Выполнение `db_init.sql`:**
   - **Создание роли:** создается пользователь `auth_app` с правом логина (`LOGIN`) и паролем из переменной окружения.
   - **Создание базы данных:** создается база данных `auth_db`, владельцем которой назначается `auth_app`.
   - **Создание схемы:** в БД `auth_db` создается схема `auth` с авторизацией для `auth_app`.
   - **Назначение прав:** роли `auth_app` выдаются полные необходимые привилегии (`CONNECT`, `CREATE`, `TEMPORARY` на БД и `USAGE`, `CREATE` на схему `auth`).
   - **Настройка `search_path`:** для роли `auth_app` в БД `auth_db` настраивается путь поиска схем по умолчанию (`auth, public`).

4. **Дальнейшее создание таблиц:**
   - Инициализация таблиц и структуры данных (например, таблицы `users`) не входит в начальный SQL-скрипт и выполняется самим приложением `auth-service` через механизм миграций Liquibase.

## Переменные окружения (`.env`)

Для работы `docker-compose.yml` в каталоге `docker/` должен присутствовать файл `.env` со следующими переменными:

```env
POSTGRES_PASSWORD=your_postgres_admin_password
AUTH_APP_PASSWORD=your_auth_app_password
```

---

## Параметры подключения

- **Хост:** `localhost` (или имя контейнера в docker-сети)
- **Порт на хосте:** `55432`
- **Порт внутри контейнера:** `5432`
- **База данных:** `auth_db`
- **Схема:** `auth`
- **Пользователь приложения:** `auth_app`
- **Пароль приложения:** значение переменной `AUTH_APP_PASSWORD`

## Команды управления

### Запуск базы данных
```bash
docker compose up -d
```

### Остановка
```bash
docker compose down
```

### Полный сброс и повторная инициализация
Скрипты из `/docker-entrypoint-initdb.d/` срабатывают только при отсутствии существующей базы данных. Чтобы переинициализировать БД с нуля, необходимо удалить том с данными:

```bash
docker compose down
rm -rf db-data
docker compose up -d
```
